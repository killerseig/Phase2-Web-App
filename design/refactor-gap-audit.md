# Refactor Gap Audit

Date: 2026-07-06

Scope: Actual Vue/Firebase codebase compared against the current refactor design docs. This is a planning artifact, not an implementation slice.

Guardrails:

- Do not start a broad rewrite from this audit.
- Preserve existing `data-testid` contracts.
- Refactor in small, reversible slices.
- Do not mix UI extraction with Firestore Rules, Cloud Functions, PDFs, or email rendering.
- Treat the timecard workbook/PDF visuals as protected output unless the slice is specifically about timecards.

## A. Executive Summary

The current refactor execution board is complete except for the intentionally deferred Firestore/Storage Rules emulator suite (`R08`). E2E coverage is much better than it was, the user-facing draft/view-first regressions are represented in tests, the frontend has a service layer instead of Firebase calls scattered through components, and the final closeout gates are green.

The app has completed the `R07` rollout from the older `admin` / `foreman` / temporary `project-manager-as-foreman` model to the target capability-based model with Admin, Payroll, Shop Foreman, Project Manager, and Foreman at the app/function/policy-test layer. The frontend now has role helpers, target-backed live capabilities, named route capabilities, a pure tested router access decision seam, live `/dashboard` role landing route, role-dashboard job shortcuts, granular Jobs UI permissions for Admin/Payroll/Project Manager setup boundaries, all-job visibility capability checks, Jobs management capability checks, Timecard Export capability checks, Daily Log visibility capability checks, Job Timecard management capability checks, assigned Project Manager submitted-timecard reporting, Payroll employee/timecard-export browser coverage, Payroll field-workflow denial coverage, Shop Foreman Shop Catalog browser coverage, Shop Foreman Shop workflow and all-jobs-read-only browser coverage, PM unassigned-dashboard denial coverage, Foreman admin-surface denial coverage, a tested target-role capability matrix, and a tested target job-access policy. Direct job routes now hydrate the first visible-job snapshot before access decisions when the route depends on job identity. The frontend and Cloud Functions now preserve the same live stored role catalog, Firestore Rules and Storage Rules have an initial target-role bridge, and Functions have tested target-role, target job-access, target field-workflow, target field-email recipient, and target timecard-access policy seams that mirror the frontend target policy. The remaining role/security caveat is direct rules emulator coverage, which remains deferred under `R08`.

The next major gap is size and coupling. Several route views are still acting as mini-apps: they own rendering, state orchestration, autosave, validation, confirmation, Firestore calls through services, and workflow rules in one file. Those are now next-phase slices rather than blockers to the current board.

The remaining lower-layer verification caveat is direct Firestore/Storage Rules emulator coverage. E2E is strong, many function/composable/component seams now have focused unit tests, and architecture-boundary tests protect the Firebase service boundary, but Rules emulator coverage stays deferred until `R08` is reintroduced.

Verdict: the current board is complete for the requested pass, with `R08` intentionally deferred. Continue future work as small, test-backed slices: route-view composition cleanup, output-builder splitting, query/index cleanup, bundle/code-splitting, and generated-artifact/legacy-fallback cleanup.

## N. No-Go Conditions

Do not continue a refactor slice if any of these are true:

- A touched workflow does not have a targeted E2E test.
- A component extraction requires changing Firestore Rules, Cloud Functions, and UI in the same PR/slice.
- A shared component imports Firebase SDK directly.
- A view-first workflow starts creating drafts/items during navigation.
- A timecard PDF/workbook visual changes outside a dedicated timecard output slice.
- A shop order PDF/email change cannot be previewed or smoke-tested with a long multi-page order.
- A role/rules change is made without emulator tests or a written rollback path.
- A query change broadens access or reads without checking rules and indexes.
- `data-testid` values used by E2E are removed or renamed without updating tests in the same slice.
- The app becomes slower or disables typing while a save is pending.
