## Workflow ownership review — November 7, 2026

The private foundation index and its Modular Design and Vue standards were accessible and reviewed for this pass (foundation version 1.0). Their rules are applied through the contracts and tests below; the private standards are not copied into the repository. No new framework, service, tenancy or entitlement model is adopted. The process guide remains the single command/release/handoff reference.

| Workflow and entry | State/data owner and permission boundary | Recovery and verification owner |
| --- | --- | --- |
| Sign in / sign out (`/login`) | `stores/auth.ts` owns browser session/profile lifetime; `services/auth.ts` adapts Firebase. Active profiles and server checks remain authoritative. Jobs and timecard export caches are session-owned. | Three attempts per hydration; one listener-recovery timer at a time; old session results/listeners must not change a new session. `authStoreLifecycle.spec.ts`, `authService.spec.ts`, route-access units and Employee browser journeys. |

One Job template serves all jobs; Job notes/calendar are job-shared and currently Admin-write-only. | Explicit save/cancel, version conflicts, nested pending-draft guards and Undo. `e2e/dashboard-*.spec.ts`, `shared-dashboards.spec.ts`; backend assertions in `scripts/verify-shared-dashboards.mjs` are separate evidence. |
| Library / supplied references (`/company-library`, existing document widget) | Explorer owns local navigation/metadata drafts; query, mutation, book export and authorized file delivery have separate lifetimes. The role/capability inventory is defined by `src/auth/targetRoleCapabilities.ts`, `src/router/routeAccess.ts` and `src/features/navigation/appShellNavigation.ts`, not historical stakeholder job titles. In particular, Payroll creates/looks up jobs and exports/locks timecards but does not edit existing job setup; PM edits assigned setup and reviews submitted timecards. The existing unassigned timecard-route exception in `useJobTimecardAccess.ts` remains unchanged. See the [role-session plan](../next-update/03-workspace-design.md#role-based-usability-sessions--november-7-2026) for human tasks and the [editor inventory](../next-update/08-widget-layouts.md#all-editor-parity-inventory--november-7-2026) for deliberate differences and remaining work.

### Bounded refinement findings

| Priority | Evidence and action | Remaining boundary |
| --- | --- | --- |
| High | Auth profile hydration, listener retry and old listener callbacks could outlive their session. Consolidate ownership and reject stale completions; verify with delayed service results, failed retries and overlapping login callbacks. | Frontend lifetime fixes do not change Firebase authentication, profile creation, role values or server authorization. |
| High | Private reference readers only checked access on entry and retained loaded text after role/account changes. Require explicit access/context inputs, synchronously clear and abort on change, and reject late query/read/error results. Update all three consumers. | Backend ticket authorization remains authoritative; no persistent content cache or new access capability. |
| Medium | Explorer watched the entire profile object; changing a name discarded an open draft and repeated its library reads. Observe the stable UID/access/role/active/assignment set instead. | Actual access changes still invalidate the editing context. This is not a general mutation-cancellation redesign. |
| High — corrected in the Form lifetime pass | Deferred tests reproduced UID-only list races, unconditional busy cleanup, obsolete confirmation/reload effects and lost duplicate retry keys. Shared context and request generations now cover persistence and adjacent read/import/select/remove/duplicate/navigation callers. | Already-sent mutations cannot be canceled by these frontend guards. Failed-refresh recovery remains explicit; server Admin authorization and immutable issued records are unchanged. See the latest workspace checkpoint for actual verification. |
| Follow-up | Website keyboard and clipboard semantics differ from the agreed dashboard reference; Forms has a different semantic model. | Use the finite editor inventory; do not hide compatibility changes inside a cleanup. |

This pass prioritizes observable lifetime failures and redundant requests over file-size-driven extraction. Existing cohesive helpers remain in place. No new caching layer, dynamic module registry, saved geometry format, permission expansion or untrusted-content execution path is introduced.
