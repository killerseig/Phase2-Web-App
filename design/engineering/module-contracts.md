# Module contracts

Use this index to load the relevant boundary first, then inspect source/tests when changing it or when evidence conflicts. These cards describe existing behavior as of November 6, 2026; commercial module interfaces and general company entitlements remain proposals. Each card should stay short enough to review alongside a change.

## Contract card format

Record purpose/nonresponsibilities; public entry points and types; inputs/outputs and units; invariants/state ownership; side effects, errors, cleanup and retry behavior; permissions and scope; required/optional dependencies; source and behavioral tests. Add a usage example when it clarifies the contract. Update the card when callers' observable behavior changes, not for every internal line edit.

## Form authoring

**Interface:** `useFormAuthoring(draft, dirty)` returns selection/select/reset/saved/undo/redo and reactive availability flags. Inputs are Vue refs; history snapshots cover the form definition and selected field, not network state. Reset establishes a baseline; `saved()` marks the current definition saved. Undo/redo retain stable field IDs and restore optional definition properties correctly.

**Ownership and effects:** mutates the caller's draft/dirty refs and manages bounded local history/watchers. No server writes or authorization. The view owns account/scope reset and navigation; persistence owns successful-save notification.

## Form persistence

**Interface:** `useFormPersistence(options)` coordinates device library storage, server template loading/saving and confirmed save-before-publish. Options supply UID/draft/library/status refs, storage, authoring callbacks and confirmation. Returned operations/status are the authoritative persistence boundary; the view retains field editing and navigation.

**Invariants and effects:** device versions and server revisions are different concepts. Successful saves/publication have owner/draft guards; issuing follows a successful save and confirmation. The implementation does not guard every error/finally update by request generation, and server loading checks UID only. Callers must preserve its existing lifetime constraints; this is not a complete stale-result isolation guarantee. Uses local storage and Admin template transport. Server handlers independently authorize Admin access and validate immutable issuance; a client flag cannot grant it. Busy/error/publication state reports failures without silently declaring a draft published.

[Source](../../src/features/forms/useFormPersistence.ts) · [Tests](../../src/features/forms/useFormPersistence.spec.ts)

## Website editing and commands

**Interfaces:** `useWebsiteWidgetEditing(options)` owns selection, inspector context and widget geometry operations; `useWebsiteCommands(options)` returns `load` and `command` to coordinate explicit persistence/publication. Both compose injected editor state and the existing history/autosave/draft-sync boundaries.

**Invariants and effects:** there is one editable site state; geometry/selection is separate from publication. Selection and layout changes preserve IDs/references. Commands may call Website services and confirmation callbacks; editor operations do not independently publish. Account/scope and stale-result guards remain necessary. Admin authorization and public rendering are enforced at their existing server/renderer boundaries.

## Library mutation lifetime

**Interface:** `useLibraryMutation({busy,error,progress}).runMutation(operation)` supplies a `stageFile(File)` callback returning uploaded metadata. One mutation stages one file; the caller owns file validation, metadata commands, navigation and success UI.

**Effects and limits:** the helper sets busy/progress, maps operation errors and awaits staging cleanup in `finally`. It does not grant document access, renew viewer tickets or own byte ranges. Cleanup failures can reject; callers must not assume arbitrary operations are idempotent or use this as a batch transaction. Backend upload/metadata services remain the permission boundary.

## Authorized document requests

**Interface:** `createAuthorizedFetch(url,{signal,isCurrent,renew?,onRenewing?}).request(init?)` returns a successful `Response` or throws. The caller supplies viewer lifetime and optional ticket renewal; the helper normalizes the file URL and sends no-store requests.

**Invariants and effects:** an expired-ticket response may cause one renewed retry per request; concurrent expired ranges share a renewal. Other denials do not renew indefinitely. Abort or changed-view checks run around asynchronous work. A renewed link is not a new access grant: the renewal service rechecks permission. Keep this instance scoped to one viewer; do not share it across owners/documents.

## Dashboard transport and server model

**Interface:** `sharedDashboardCommand(action,data)` maps typed actions to typed responses through `sharedDashboardWorkspace`. Context contains personal/job/role scope and optional job/role identifiers; personal ownership is derived server-side. For example:

```ts
const layout = await sharedDashboardCommand('load', { scope: 'personal' })
// Save with layout.version; never substitute notesVersion for a template revision.
```

**Invariants:** template version and private-content version are separate. Copy/group operations move configuration, not saved private notes, submissions or documents. Role templates are Admin-owned with explicit default-off delegation; Job templates are Admin-owned. Every request still checks active identity and authorized scope. Client workspace availability is not authorization.

**Model:** `validateSharedWidgets` and `validateDashboardViewport` are pure shape/bounds validators, not permission checks. Layouts contain at most 12 widgets including descendants, bounded 24-column placement, bounded nesting and required Job/Role navigation tools (Personal may be empty). Containers retain a flat ID/parent/region graph. Tablet/phone overrides are optional; absent overrides inherit desktop behavior. Invalid saved display/hierarchy data produces a controlled server error without rewriting the record.

**Effects and dependencies:** the client uses Firebase callable transport; the handler uses Admin transactions and issued-form checks. The client exposes typed actions; the server validates action/data at runtime, and saves detect revision conflicts. No contract here grants production deployment or changes legacy workflows.

## Dashboard geometry and pointer lifetime

**Responsive widget presentation:** shared headers and task/resource actions wrap within the authored card. Non-container content keeps a minimum readable width of 160 CSS pixels; narrower cards retain their authored bounds and use focusable local scrolling. Container regions keep parent-local geometry, and long tab labels wrap without changing their keyboard order. Inline Form presentation stacks its header at its own container width; standalone form headers keep their existing behavior. These are presentation rules, not schema migrations or implicit saves.

`DocumentExplorer` owns one opt-in drawer state for both presentation and focus/inert behavior. With `sidebarTools`, its untransformed observed width at or below 600px or the existing browser breakpoint at 900px activates the drawer. Zero-width hidden tabs retain their prior state; same-mode observations do not close an open drawer. Mode changes close menus and return disappearing sidebar/menu/trigger focus to a surviving control. The observer and media/key listeners are disposed on unmount. Desktop narrow cards retain mouse/keyboard zoom; phone layouts retain compact controls and native pinch. Legacy explorers without `sidebarTools` keep their existing layout. [Responsive catalog cases](../../e2e/dashboard-catalog-responsive.spec.ts) · [Explorer focus/lifecycle units](../../src/__tests__/DocumentExplorer.spec.ts) · [Standalone touch regression](../../e2e/library-mobile.spec.ts)

**Container reassignment:** `widgetMove.ts` validates and plans one atomic change for every outermost selected root. Pointer moves project Desktop physical dimensions and relative gaps into the destination's parent-local 24-column/32px-row coordinates; descendants keep local geometry. Common bounds/snapping translate the group without independently resizing or clamping members. The keyboard-accessible Container/region selectors use the same planner while preserving exact numeric local placements. Reassignment is Desktop-only in both paths because hierarchy is shared across devices. Explicit Tablet/Phone placements remain unchanged and become relative to the new parent; this does not promise identical screen positions in those views. Tablet/Phone support ordinary within-region movement. All paths retain IDs, private records, required tools, authored overrides and unrelated regions, and enforce source/destination position locks, hierarchy, depth, type/count and size bounds.

Visible hit testing selects the deepest accepted region, ignoring the moving subtrees and selection/preview overlays. Headers, tab buttons, gutters, hidden/clipped regions, menus and outside-canvas locations are not destinations. An ancestor overlay covering a nested selection does not pull that selection out while the pointer remains in its clipped source area; leaving that area permits moving to the ancestor. Tabs must be opened before direct dropping. The inspector can assign a hidden positioned/empty region, but rejects unmeasured hidden flow. Insertions/removals pin only affected source/destination fallback siblings whose layout would otherwise change; a flowing surface's direct siblings are measured without guessing. Resize stays in its original region and never materializes unrelated hidden children.

`surfaceGeometry.ts` preserves fractional CSS box measurements rather than rounded DOM client dimensions, including borders, native scrollbars and preview scale. Empty drop styling uses an outline, and destination extent includes the ghost, keeping preview and committed geometry aligned. Drag scrolling prefers the nearest scrollable region before its outer viewport. Existing-widget transactions recheck identity/access/scope/job/role/device, selection/revision, source width and camera/browser dimensions before committing. Escape, blur, pointer cancellation, obsolete state or an invalid drop makes no layout/history change. The generic drag helper's added hit-testing/geometry behavior is opt-in; Forms retains its existing ordered-drop behavior. [Move planner](../../src/features/dashboard/widgetMove.ts) · [Move units](../../src/features/dashboard/widgetMove.spec.ts) · [Browser journeys](../../e2e/dashboard-reparent.spec.ts)

**Interfaces:** `editorGeometry.ts` provides resize/translate/arrange, selection roots, descendant expansion and inherited geometry locks. `widgetClipboard.ts` owns configuration capture/remapping and bounded copy placement. Positions use 24 logical columns and 32px rows; render scale is separate. `useWidgetDrag` owns threshold, grab offset, pointer cancellation, drop targeting and scroll assistance; the view owns persistence and the selected surface.

**Invariants and effects:** geometry locks constrain editing but never confer permission. Opposite resize edges stay anchored; group movement preserves offsets within bounds. Clipboard remaps IDs/parents and clears legacy note text. Responsive edits affect the chosen widget/device rather than freezing all other devices. Escape/blur cancels uncommitted pointer work; handlers/listeners are removed on disposal. Pure geometry functions do not access Firestore. DOM measurement belongs to the view/canvas.

**Selection locks:** `selectionLocks.ts` derives effective checked/mixed state from outermost selected roots, with separate counts for direct and inherited locks and names of controlling ancestors. The inspector exposes native indeterminate state and accessible mixed state. Commands change only those roots' own flags; selecting a parent and child does not rewrite the child's flag. If any root inherits the requested lock, that whole axis command is unavailable; ancestors are never implicitly unlocked and the other lock axis remains independent. Semantically unchanged flags return the original array and do not dirty history. The context menu explicitly selects the clicked widget and uses the same state/action helper for that singleton. Busy/access, active gestures, pending removal and obsolete selection/context/layout events cannot apply lock commands. Reactive gesture/confirmation flags restore enabled controls after cleanup. Group move/resize and arrangement eligibility are atomic, with independent size-only rules described below. [Lock state/actions](../../src/features/dashboard/selectionLocks.ts) · [Lock units](../../src/features/dashboard/selectionLocks.spec.ts) · [Lock browser coverage](../../e2e/dashboard-selection-locks.spec.ts)

**Selection arrangements:** `selectionArrangement.ts` shares root count, common parent/region and relevant effective-lock eligibility between controls and execution. Align/distribute reject any position-locked root; Match size rejects any size-locked root but permits position locks when origins stay fixed and the requested size fits every root. A primary child resolves to its selected ancestor. Geometry changes only the intended coordinate/dimension; distribution pins both endpoints ordered by origin and calculates equal edge gaps, allowing overlaps only within bounds. No grid quantization or per-target size clipping occurs. Arithmetic no-ops retain original geometry/arrays and create no history entry. Invalid or unmeasurable proposals are rejected atomically with visible and accessible feedback.

Already-positioned regions use the canvas's surface-local fallback order and patch only changed selected roots. For a real first placement in flow, validated direct-child rectangles preserve every sibling in that same region; no other container, hidden tab or descendant is materialized. Measurement accounts for scale, client width, border and native scroll, without rounding or guessing hidden geometry. Unrepresentable flow sizes are rejected rather than clamped. Tablet/Phone write only that device's overrides; Desktop remains the existing inherited base. The view rechecks busy/access, gestures, confirmation, selection/context/revision before applying one validated array. Obsolete controls are rejected; keyboard focus survives revision replacement and falls back to the canvas if Undo disables the prior action. This atomic policy deliberately differs from Networking's partial arrangement behavior. [Planner](../../src/features/dashboard/selectionArrangement.ts) · [Planner units](../../src/features/dashboard/selectionArrangement.spec.ts) · [Browser coverage](../../e2e/dashboard-arrangement.spec.ts)

**Keyboard geometry and selection:** `keyboardGeometry` adds relative configured-spacing deltas for arrows and one screen pixel for Shift+Arrow, using the actual root/nested surface width and render scale. It retains off-grid offsets rather than re-snapping the absolute origin. Group movement clamps one delta; keyboard resize uses the existing edge/group rules with six-decimal precision, while pointer rounding keeps its existing default. A no-op returns unchanged geometry and creates no layout/history entry. The view uses one selection eligibility check for direct dragging, grips and keyboard commands: every root must share its parent/region, and a blocked member blocks the group rather than silently moving a subset. Existing single-widget edge-lock behavior remains intact.

Enter/Space selects a focused canvas article; Shift/Ctrl/Command toggles it. Escape clears canvas selection or a blank root/nested canvas click clears it, without saving. Nested blank clicks do not bubble into selecting the ancestor container. Marquee selection adds only to existing selections in its own parent/region, so a selected ancestor cannot swallow newly selected children; cancellation restores the original full selection. Input, menu, tab and dialog keyboard handling retains precedence. Active drag/background gestures own cancellation and reject keyboard-driven selection or transforms until finished; Escape restores their initial state before a later Escape may dismiss selection. A disappearing focused peg returns focus to the canvas. Runtime receives none of these authoring commands.

The mount continuation checks disposal after each awaited initialization boundary, preventing late loads, observers and `beforeunload` listeners after cleanup. Existing request-generation guards still own stale response handling. This introduces no backend, permission or saved-layout schema change.

**Configuration clipboard:** capture selects roots and their descendants once, strips legacy note text and records source identity/scope/role/job. Mixed parent/region root selections are rejected with feedback; an invalid copy leaves the old clipboard intact. Clipboard state stays inside this editor instance and clears on account/role/access changes. Internal parents receive fresh IDs. An external parent/region survives only within the same source context while still valid; another context's same-named parent is never reused. Explicit locks and valid inherited locks remain, while geometry locks retain their existing meaning rather than becoming deletion permissions.

Paste and Duplicate share one materializer. It translates roots together with one bounded delta across desktop and authored device overrides, preserving sizes, fractional offsets, missing overrides and descendant-local geometry. Current sibling occupancy determines the first unused cascade position; Undo frees that position. Ordinary partial overlap is allowed, but exact coincident root footprints are skipped. The finite nearby search checks all axis/diagonal directions and fails without mutation when none is found. Fully flowing destinations remain flow; flow copies entering positioned surfaces receive their own placement without rewriting existing widgets. The caller rechecks available types and validates the complete result (singleton types, hierarchy, required tools and 12-widget limit) before one atomic history change. Copies never contain saved private records.

Ctrl/Command+C/V/D/X and Delete/Backspace are recognized only from the canvas, outline or selection controls in Edit. Input/contenteditable, menus, dialogs and tabs retain their keys; held keys, busy/unavailable editing and active gestures cannot repeat/mutate these operations. Recognized shortcuts during a gesture are consumed so Ctrl+D does not become a browser bookmark action. Remove/Cut cover the selected root subtrees, reject any required descendant, and require confirmation. Cut explicitly copies **settings**, creates fresh widget identities on Paste, and retains saved content at the original records. Cancellation, failed validation or a stale context/edit revision leaves both layout and previous clipboard intact. Successful Cut replaces the clipboard only after validated removal; Undo restores original IDs. No content-delete calls are made.

**Pointer-anchored Paste:** `useClipboardPointer.ts` stores only an idle primary mouse/pen client point and its surface identity. At use it rechecks the live hit-tested visible client box, geometry and editor permission/gesture state; coordinates account for surface borders/native scrolling and rendered scale. Pointer leave, touch/pressed movement, cancellation, blur, resize, native scroll, context/device/camera changes and Cut/Remove confirmation invalidate the hover. Tab visibility/selection transitions invalidate it, while ordinary tab-canvas extent growth preserves repeated paste. Listeners and observer are disposed. The pure clipboard planner accepts a surface-qualified anchor only for the resolved destination region on a positioned surface. It centers active-device root bounds, snaps one stable root when enabled, then shares one bounded delta across every authored view. It tries the anchor before nearby unoccupied offsets. No implicit reparenting, source mutation, saved-coordinate expansion or flow conversion is introduced. Duplicate never passes an anchor. It draws minor/major dots at the same 24-column/32px-row intersections used by snapping, above opaque widgets so full-width tools cannot hide the guide. The SVG is decorative and never receives pointer events. Each canvas masks direct containers out of its grid; nested canvases draw their own local intersections. **Workspace grid and camera:** `useDashboardWorkspaceGrid({viewport,content,active,spacing,dependency})` measures the root canvas relative to the viewport and paints only the viewport's seven background properties. It follows native scrolling, resize, camera translation and scale through one scheduled animation frame, without re-rendering the editor or changing a draft. This protects uncommitted number-input text from measurement updates. It removes its styles/listeners/observers on replacement or disposal; inactive mode removes the background. The opaque edit canvas draws its own grid, preventing doubled dots.

`viewportGeometry.ts` owns pure camera conversion: saved starting offsets use 24-column/32px-row units; pointer deltas convert from screen pixels through the current scale. Non-finite pan input preserves the original camera. Origin and actual-size controls change local view state only; they do not alter the saved starting view or widget positions.

**Editor fitting:** Fit frame centers the resolved desktop frame; Fit content centers the current device's direct root widget bounds, rounded outward to grid cells, with empty content falling back to the frame. Nested content is clipped by its root container and does not expand that union. DOM measurements are converted to logical pixels; a 1/16px tolerance prevents percentage-layout quantization from adding a spurious cell. Both commands fit width and height with 24px screen padding, never upscale beyond 100%, and may go below the manual/runtime zoom floor. Manual Zoom out is disabled at/below 25%, so a small fitted view cannot zoom inward on a Zoom out action. Selection pegs retain their 24px screen size.

Fitting is a one-shot local camera/zoom/scroll operation, excluded from dirty state, history and server writes. Bounded post-render corrections handle automatic margins and native scrollbars; generation/auth/scope/device/DOM guards cancel stale work. Opening Edit retains the existing automatic width-fit default. After an explicit fit, viewport resizing preserves the scale; changing device resets to the established width-fit/origin view before any new fit command. Pan, manual zoom, Origin, outline reveal and widget transforms cancel pending fitting. Legacy root flow rows align at the start in editing instead of stretching into the empty workspace. Saved viewport/start/placement bounds, runtime behavior and permissions are unchanged.

**Independent published frame:** `DashboardViewport.publishedFrame?` is an optional `{x,y,width,height}` rectangle in authored canvas pixels. Signed origins are finite and bounded to ±10,000; width stays 320–3,840 and height 240–4,000. Strict browser/server validation rejects malformed/extra fields. Absence preserves the old viewport record and rendering path; loading does not migrate records. `DashboardPublishedFrame` presents the existing move grip/eight circular resize controls with an amber dashed border in Desktop editing. Its interior passes pointer events through. **Selection frame:** `DashboardSelectionFrame` receives bounds in its host canvas's 24-column/32px-row coordinates and emits move, eight-direction resize and keyboard intents. `SharedDashboardCanvas` shows the same overlay for a single selection or multiple selected roots sharing a parent and region. The `scale` input keeps all eight circular resize targets at 24 screen pixels; single selections supply `widgetTitle` for their accessible names. Positioned widgets use the current preview geometry; legacy flow widgets use locally observed content-coordinate bounds. One root overlay hosts nested controls above authored sibling/ancestor layers. The selected nested canvas projects its bounds into that overlay, accounting for scrollbars, scroll offsets and transforms; clipping ancestors still clip the controls. Its animation frame and observers are canceled on disposal. The pointer helper retains the original common surface/origin for frame controls outside a widget. **Widget menus and layers:** the same edit-only menu opens from a widget or its outline row, including Shift+F10. It clamps to the viewport, supports keyboard navigation and restores the invoking control on Escape; outside clicks keep their intended focus. Runtime keeps native context menus. **Clipped-control accessibility:** the nested canvas supplies its intersected screen clipping rectangle to `DashboardSelectionFrame`. Measurement uses the selected canvas's existing projection updates and Vue's scoped watcher; it adds no persistent observer or global event listener.

`widgetLayers.ts` treats sibling array order as back-to-front order. Reordering changes only the slots belonging to the same parent/region, leaving other subtrees untouched. Selection does not raise a widget. Layer edits remain ordinary undoable layout changes; no separate z-index field or server contract is introduced.

## Announcement management and entry delivery

**Interface:** `/admin/announcements` uses `load-announcement-drafts`, `save-announcement-drafts` and `publish-announcement` through the existing shared dashboard callable. The new load returns only the caller's drafts, private-content version and published draft IDs. Admin authoring no longer requires a valid personal layout or a drafts widget. Existing author-owned storage/versioning and saved widget clients remain compatible; saving drafts preserves other content. Published snapshots remain immutable and idempotent by author/draft ID.

**Authority:** every command resolves the current active profile on the server. Draft operations are Admin-only, personal-scope and caller-owned; unexpected identity/role/extra fields fail. Everyone, current job assignment and explicit-person audience checks are unchanged, including Employee's narrow personal-feed exception. No shared Admin draft access, new group model, tenant model or outbound email is introduced. The standalone employee inbox and paused My Timecard workflow remain intact.

**Delivery:** `useAnnouncementDelivery` owns per-app request state; `AnnouncementDelivery` supplies authenticated route context and renders the native modal. Initial protected-app entry (including refresh/direct login to a job) fetches the personal feed once. Subsequent entry to a job fetches that job's eligible feed; child routes/query changes within the same job do not repeat it. All returned updates appear together, newest first, up to the existing 50-item feed bound. Continue, close and Escape dismiss only this visit. No acknowledgment/read receipt is stored; a later login or job re-entry may show the same updates. Public routes and revoked access clear the modal, and generation checks reject stale identity/context responses. Failure leaves navigation available with retry/dismiss controls. Focus is contained/restored, content scrolls inside the viewport, and plain text never becomes HTML.

**Limits:** this is entry-time delivery, not a live subscription or guaranteed unread inbox. Withdrawal, expiry, scheduled publishing, mandatory acknowledgment and arbitrary groups remain separate decisions. The compatible backend must precede a later authorized frontend deployment.
